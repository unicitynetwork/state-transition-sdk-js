# CBOR text-string vectors (member ids and witness keys)

`vectors.json` is generated by Go, not here, and must not be edited:

- Generator: `generator_test.go.txt`. Copy it to `types/` in `unicitynetwork/bft-go-base` at `dbf94198` (bft-go-base#20 merged) and run `TEXT_VECTORS_OUT=<file> go test ./types -run TestTextStringVectors`. It asserts Go's own outcome for every case before writing the file.
- sha256: `941d63463d16756c6a60a888e45026987fa3440d2d0621ae2d002d0ed52ac0e6`.
- Shared with the Rust and Java SDKs (briefs: shared-fixes).

Rule: a text string decodes byte for byte. A leading U+FEFF is part of the string, and invalid UTF-8 is refused. Ids that differ only by a leading U+FEFF are different members, and each one's signature counts.

The committee is a genesis entry with members `node-a`, `node-b` and `U+FEFF node-a`. `decode` contains that entry (valid; re-encodes identically) and the same entry with one member id made invalid UTF-8 (refused as an encoding error). `seals` contains a quorum of 3 that counts the BOM twin (valid) and a weight of 2 (below the quorum).
